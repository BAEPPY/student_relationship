# 학생 관계 마인드맵

학생들이 각자 친구 관계를 마인드맵처럼 표시하면, 교사가 학급 전체의 관계를 종합적으로 확인하고 갈등 가능성을 미리 살펴볼 수 있는 웹 앱입니다.

## 주요 기능

**교사**
- 교실을 만들고 학생 이름을 등록하면 학생마다 개인 QR 링크가 만들어집니다.
- 명단 파일 올리기: 교실을 만들 때(📄 명단 파일 올리기)나 선생님 페이지의 학생 목록(📄 명단 파일로 추가)에서 한글(.hwp, .hwpx)·워드(.docx)·텍스트(.txt) 명단 파일을 올리면 번호·이름이 있는 표(두 블록으로 나뉜 표, "3 김하늘"처럼 번호가 함께 적힌 칸도 가능)나 한 줄에 한 명씩 적힌 목록에서 학생 이름을 읽어 옵니다. 머리말(이름·번호·성별 등)과 담임 이름은 빼고, 같은 이름은 한 번만 넣으며 확인 안내를 함께 보여 줍니다. 읽은 이름은 화면에서 확인·수정한 뒤 등록하고(선생님 페이지에서는 이미 있는 학생은 건너뜀), 파일 내용은 서버에 저장하지 않습니다.
- QR 카드 인쇄 페이지에서 카드를 출력해 학생에게 한 장씩 나눠 줄 수 있습니다. (링크 목록으로 개별 전송도 가능)
- 전체 관계도: 관계(화살표)가 많은 학생은 가운데, 적은 학생은 바깥쪽에 배치됩니다.
  - 빨간 화살표 = 좋은 사이, 검은 화살표 = 안 좋은 사이
  - 화살표를 누르면 그 학생이 적은 이유를 볼 수 있습니다.
  - 학생을 누르면 그 학생의 관계만 강조되고, 받은/준 관계와 이유가 정리되어 보입니다.
  - 필터(좋은 사이만 / 안 좋은 사이만), 확대·축소, 상자 끌어서 옮기기
- 갈등 가능성 분석: 학생 쌍마다 앞으로 갈등이 생길 추정 확률(%)과 그 근거를 보여 줍니다.
- 회차(월별 조사): "새 회차 시작"을 누르면 지금 회차가 마감되고 빈 회차가 열립니다. 회차 이름은 "2026년 10월"처럼 달로 자동 제안됩니다. 학생 QR은 그대로 쓰고, 학생 화면은 지금 열린 회차에만 답하며 마감된 회차는 학생이 바꿀 수 없습니다. 회차마다 관계도·갈등 분석을 따로 볼 수 있고, 회차가 2개 이상이면 학급 추세, 새로 생긴·계속되는·해소된 갈등, 학생별 변화를 비교하는 "회차별 변화 분석"이 나타납니다.
- 자리 배정: 선생님 페이지에서 보고 있던 회차의 응답을 그대로 가져와, 저장된 자리가 없으면 열자마자 자동으로 배정합니다. 저장한 뒤 새 응답이 들어오면 알려 주고 한 번에 다시 배정할 수 있습니다. 교실 배치(예: `2x4, 2x5, 2x4`)를 입력하면 안 좋은 사이를 떨어뜨리고 고립 위험 학생을 배려하는 자리표를 만듭니다. 자리 바꾸기, 고정(📌), 친한 친구 가까이/떨어뜨리기 옵션, 저장, 인쇄를 지원합니다. 자리표는 학생 시점(칠판이 위) 외에 교탁에서 바라본 교사 시점(위아래·좌우 뒤집음)이나 위아래만 뒤집은 모습으로 바꿔 보고 그대로 인쇄할 수 있으며, 선택한 방향은 브라우저에 기억됩니다.
- 교사 메모·지정 규칙: 학생별 메모와 "앞자리 필요(👓, 시력 등)" 표시, 두 학생 사이의 "떨어뜨리기"/"가까이 앉히기" 규칙을 미리 적어 두면 자동 배정에 반영되고 좌석표와 학생 상세에서 참고할 수 있습니다. 학생에게는 보이지 않습니다.
- 한 번에 붙여넣기 → 자동 분류: 수첩이나 메모장에 적어 둔 내용을 통째로 붙여넣으면 문장마다 학생 이름을 찾아 앞자리 필요 / 떨어뜨리기 / 가까이 앉히기 / 일반 메모로 자동 분류합니다. 결과를 미리보기에서 확인하고 체크한 항목만 반영합니다. 분류는 브라우저 안에서만 처리되어 학생 정보가 외부로 나가지 않습니다.
- 학생 링크 한 번에 복사: 학생 목록의 **📋 이름 - 링크 모두 복사**(또는 미제출 학생만)로 "이름 - 링크"를 한 줄씩 복사해 클래스룸·메신저에 붙여 넣을 수 있습니다. 링크는 학생마다 비밀이므로 한 글에 모두 올리지 말고 학생별로(특정 학생에게 게시, 비공개 댓글) 보내 주세요.
- 자리 배정 참고용 몸 특징: 학생이 "나는 이런 편이에요"에서 눈·키·추위·더위를 고르면 자동 배정이 앞자리와 냉난방기 바람 자리(선생님이 표시)를 함께 고려합니다. 아래 "학생 몸 특징과 자리 환경"을 보세요.
- 1인 1역(학급 역할) 배정: 선생님 페이지의 **1인 1역** 버튼에서 역할 목록(기본 역할 15개 · 26자리)을 만들고, 학생들의 지원서와 성향 설문을 한 표에서 본 뒤 규칙 배정(또는 AI 배정)을 돌리고, 끌어다 놓기로 고쳐 확정·공개합니다. 지난달에 맡았던 역할은 이번 달 지원서와 자동 배정에서 자동으로 제외됩니다. 자세한 내용은 아래 "1인 1역 (학급 역할) 배정"을 보세요.
- 역할 자리: 자리 배정 페이지에서 1인 1역 담당 학생이 앉는 🎒 역할 자리를 지정해 두면 자동 배정·AI 자리 배정이 그 자리에 담당 학생을 앉힙니다. 아래 "역할 자리"와 "AI 자리 배정"을 보세요.
- AI 분석(선택): 서버에 `ANTHROPIC_API_KEY` 를 설정하면 학급 관계 AI 분석, AI 역할 배정, AI 자리 배정을 쓸 수 있습니다. 학생 이름은 가명(S1, S2…)으로 바꿔 보내고 결과만 저장합니다. 아래 "AI 분석 설정 (선택)"을 보세요.
- 제출 현황, 제출 마감/해제, 학생 추가·이름 변경·삭제, 응답 초기화, 링크 재발급, CSV/JSON 내보내기, 교실 삭제
- 종합 보고서: 선생님 페이지 위쪽 이동 줄의 **📑 보고서** 버튼이나 데이터 관리 카드에서 열며, 보고 있는 회차의 오늘의 요약 · 학생별 관계 · 갈등 가능성 분석 · AI 분석 · 자리 배정표 · 1인 1역 배정 · 회차별 변화를 한 문서로 모아 보여 줍니다. 브라우저에서 바로 인쇄하거나 PDF로 저장할 수 있고, 한글(.hwpx)·워드(.docx) 파일로도 내려받습니다. 선생님 페이지 곳곳의 작은 **?** 버튼을 누르면 CSV/JSON 내보내기의 차이, 최소 인원, 갈등 분석과 AI 분석이 무엇인지 짧은 설명이 떠요(인쇄에는 나오지 않음).

**학생**
- 자기 QR 링크로 접속하면 "나"를 가운데에 둔 관계 지도와 반 친구 목록이 보입니다.
- 친구마다 **좋은 사이**(이유 선택) 또는 **안 좋은 사이**(이유 필수)를 표시합니다. 이유는 객관적인 선택지 중에서 고르거나 직접 적을 수 있습니다.
- 좋은 사이와 안 좋은 사이를 각각 최소 인원(기본: 좋은 사이 3명, 안 좋은 사이 1명) 이상 표시해야 제출할 수 있고, 마감 전까지는 수정할 수 있습니다. 최소 인원은 교실을 만들 때와 선생님 페이지에서 바꿀 수 있고, 반 인원이 적으면 자동으로 줄어듭니다. 화면 위에 지금 답하는 회차 이름이 표시되고, 선생님이 새 회차를 시작하면 빈 화면에서 새로 표시합니다. 옛 화면에서 제출하면 서버가 거부하고 새로고침을 안내하므로 회차 간에 응답이 섞이지 않습니다.
- 선생님이 역할 목록을 만들어 두면 학생 화면은 ① 성향 설문 → ② 1인 1역 지원서 → ③ 친구 관계 지도 순서로 진행됩니다. 지원서는 역할 카드를 눌러 1~3지망을 고르고, 지망마다 하고 싶은 이유(10자 이상)·우리 반에 도움 되는 점·나에게 도움 되는 점을 적습니다. 지난달에 맡았던 역할은 고를 수 없고, 선생님이 배정을 공개하면 자기 역할이 화면에 보입니다.
- 학생은 자기가 표시한 내용만 볼 수 있고, 다른 학생의 답은 볼 수 없습니다.

## 연결이 안 되나요? (먼저 읽어 주세요)

이 저장소에는 **코드만** 들어 있습니다. 사이트가 열리려면 이 코드를 실행하는 **서버가 어딘가에서 켜져 있어야** 합니다.

- GitHub 페이지(github.com 주소)나 GitHub Pages 로는 열리지 않습니다. 이 앱은 Node.js 서버가 필요합니다.
- `http://localhost:3000` 은 서버를 켠 **그 컴퓨터에서만** 열립니다. 학생 스마트폰에서는 열리지 않습니다.
- 학생들이 각자 스마트폰으로 접속하려면 아래처럼 **인터넷에 배포**해야 합니다. 10분이면 됩니다.

두 가지 방법이 있습니다. 둘 다 카드 등록 없이 무료로 쓸 수 있고, GitHub 계정으로 가입합니다.

| 데이터베이스 | Vercel 안에서 Neon 무료 DB를 클릭 몇 번으로 만듭니다. 별도 가입 없음. | Neon 에 따로 가입해 연결 문자열을 붙여넣습니다. |

### 방법 A. Vercel + Neon (추천)

1. https://vercel.com 에서 **Continue with GitHub** 로 가입합니다. (Hobby 플랜, 무료)
2. 대시보드에서 **Add New… → Project** 를 누르고, 저장소 목록에서 `student_relationship` 옆의 **Import** 를 누릅니다. 처음이면 GitHub 에 Vercel 앱 설치를 허용하는 화면이 먼저 나옵니다.
3. 설정은 그대로 두고 **Deploy** 를 누릅니다. 1~2분 뒤 배포가 끝나면 **Continue to Dashboard** 를 누릅니다.
4. 프로젝트 화면 위쪽의 **Storage** 탭 → **Create Database** → **Neon** 을 고릅니다. 약관에 동의하고, Region 은 **Singapore** (가장 가까움), Plan 은 **Free** 를 고른 뒤 이름을 정하고 **Create** 를 누릅니다. Neon 계정은 이 과정에서 자동으로 만들어집니다.
5. **Connect Project** 에서 이 프로젝트를 고르고 환경(Production, Preview, Development)을 모두 체크한 뒤 연결합니다.
6. **Deployments** 탭에서 가장 위의 배포 오른쪽 **⋯** 메뉴 → **Redeploy** 를 누릅니다. (DB 연결 정보를 반영하기 위해 한 번 다시 배포합니다.)
7. 왼쪽 메뉴 **Domains** 에서 **Production** 표시가 붙은 `https://student-relationship-….vercel.app` 주소가 사이트 주소입니다. 첫 화면 위에 빨간 경고가 보이지 않으면 DB 연결까지 끝난 것입니다.

주의: 배포 목록이나 주소창에 보이는 `student-relationship-abc123xyz-….vercel.app` 처럼 가운데 무작위 코드가 든 주소는 배포 한 건에만 붙는 임시 주소이고 Vercel 로그인 보호가 걸려 있어 학생이 열 수 없습니다. 항상 Domains 의 Production 주소를 쓰세요. QR 카드는 인쇄할 때 열려 있는 주소를 그대로 담으므로, 인쇄도 반드시 그 주소로 접속한 상태에서 하세요. 더 확실하게 하려면 **Settings → Environment Variables** 에 `BASE_URL` 을 그 주소로 넣고 Redeploy 하면 어떤 주소로 접속하든 QR 과 링크에는 항상 Production 주소가 들어갑니다.

버튼 한 번으로 하고 싶다면 아래 버튼을 눌러도 됩니다. 이 버튼은 저장소 **복사본**(`student-relationship-site`)을 내 GitHub 에 만들고 Neon DB 생성까지 한 흐름으로 진행합니다. 다만 이후 원본 저장소를 고쳐도 복사본에는 반영되지 않으니, 코드를 계속 고칠 계획이면 위의 Import 방법을 쓰세요.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FBAEPPY%2Fstudent_relationship&project-name=student-relationship&repository-name=student-relationship-site&products=%5B%7B%22type%22%3A%22integration%22%2C%22integrationSlug%22%3A%22neon%22%2C%22productSlug%22%3A%22neon%22%2C%22protocol%22%3A%22storage%22%7D%5D)

결제 수단을 등록하라는 화면이 나오면 (Neon 을 Vercel 안에서 만들 때 드물게 요구할 수 있음)

등록하지 말고 Neon 에 직접 가입해서 연결하면 됩니다. Neon 무료 플랜은 카드가 필요 없습니다.

1. https://neon.tech 에서 가입하고 **New project** 를 만듭니다. Region 은 **Asia Pacific (Singapore)** 를 고릅니다.
2. 프로젝트 화면의 **Connect** 버튼을 눌러 `postgresql://` 로 시작하는 연결 문자열을 복사합니다.
3. Vercel 프로젝트 화면에서 **Settings → Environment Variables** 로 가서 Key 에 `DATABASE_URL`, Value 에 복사한 문자열을 넣고, 환경(Production, Preview, Development)을 모두 체크한 뒤 **Save** 를 누릅니다.
4. **Deployments** 탭에서 맨 위 배포의 **⋯** 메뉴 → **Redeploy** 를 누릅니다.

알아 둘 점
- 코드를 GitHub 에 올리면 Vercel 이 자동으로 다시 배포합니다.
- 함수 실행 위치는 `vercel.json` 에서 싱가포르(`sin1`)로 두었습니다. Neon 도 싱가포르를 고르면 가장 빠릅니다.
- 배포 후 첫 화면이나 선생님 페이지에 "데이터베이스가 연결되지 않아…" 경고가 보이면 4~6단계를 다시 확인하세요.

## 회차(월별 조사) 동작 방식

- 교실 안의 응답은 회차별로 따로 저장됩니다. 학생은 항상 가장 최근 회차(열려 있는 회차)에만 답합니다.
- "새 회차 시작"은 지금 회차를 마감하고 빈 회차를 엽니다. 지난 회차는 다시 열 수 없고(읽기 전용), 가장 최근 회차만 마감/마감 해제가 됩니다.
- 학생 저장 요청에는 회차 번호가 함께 들어가며, 새 회차가 시작된 뒤 옛 화면에서 보낸 요청은 거부됩니다.
- 회차별 변화 분석의 "새로 생긴 갈등"은 지난 회차에 없던 안 좋은 사이가 이번 회차에 생긴 쌍, "해소된 갈등"은 지난 회차에 있던 안 좋은 사이가 이번 회차에 사라진 쌍(응답한 학생 기준), "계속되는 갈등"은 두 회차 모두 있는 쌍입니다.
- CSV 내보내기에는 회차 열이 있고, JSON 내보내기에는 모든 회차의 관계와 분석, 변화 분석이 들어갑니다.
- 회차 기능 이전에 만든 교실은 처음 열 때 기존 응답이 1회차로 자동 변환됩니다.

## 1인 1역 (학급 역할) 배정

선생님 페이지의 **1인 1역** 버튼(`/t/<선생님 링크>/roles`)에서 달마다 학급 역할을 배정합니다. 회차(월별 조사)와 같은 단위로 돌아가며, 회차 이름이 "2026년 10월"처럼 달 이름이면 지난달 기록과 자동으로 이어집니다.

**선생님 흐름**

1. 역할 목록 만들기: "기본 역할 15개 불러오기"(26자리)를 누르거나 직접 만듭니다. 역할마다 이름(40자)·부제·인원(1~10명)·설명(600자)을 적을 수 있고, 이름과 설명은 학생 지원서에 그대로 보입니다. 역할이 있어야 학생 화면에 지원서 단계가 열립니다.
2. 지난달 현황 가져오기(처음 한 번): 지난달 배정표를 붙여넣거나 한글·워드 파일을 올려 미리보기로 확인한 뒤 "이 달 기록으로 저장"하면 같은 역할 연속 금지 규칙이 바로 적용됩니다. 그다음 달부터는 배정을 확정·공개할 때 그 달 기록이 자동으로 저장되므로 다시 가져올 필요가 없습니다.
3. 학생 응답 기다리기: 학생은 자기 QR 링크에서 ① 성향 설문 → ② 1인 1역 지원서 → ③ 친구 관계 지도 순서로 답합니다. 지원 현황 표에서 아직 지원서를 내지 않은 학생을 볼 수 있습니다.
4. 지원 현황 확인: 역할마다 1·2·3지망 지원자 수, 학생마다 지망·이유·성향·"성의"(이유 글자 수와 도움 칸을 채웠는지)를 한 표에서 봅니다. 선생님의 선정 기준 4가지(역할을 잘 이해했는지, 이유를 성의껏 적었는지, 이전 활동을 열심히 했는지, 지원자가 몰리지 않았는지)도 함께 표시됩니다.
5. 자동 배정: "규칙 배정"은 서버에서 바로 계산하고, "다시 섞기"는 같은 점수인 지망의 순서만 바꿔 다시 돌립니다. `ANTHROPIC_API_KEY` 가 설정되어 있으면 AI 배정도 쓸 수 있습니다. 결과는 보고 있는 회차에 초안으로 저장되고 학생에게는 아직 보이지 않습니다.
6. 직접 고치기 → 확정·공개: 이름표를 역할 카드나 "아직 배정 안 됨" 칸으로 끌어다 놓아 고치고, 학생마다 "?"를 눌러 배정 이유를 확인합니다. "초안 저장"은 선생님만 보는 상태로 저장하고, "확정하고 학생에게 공개"를 누르면 학생 화면에 자기 역할이 보이면서 그 달 기록이 저장되어 다음 달 제외 규칙에 쓰입니다. "공개 취소"로 다시 숨길 수 있고, 배정표는 복사·인쇄할 수 있습니다.

**지난달 역할 금지 규칙**

- 이번 회차 바로 전 달(가장 가까운 지난달 기록)에 맡았던 역할은 학생이 지원서에서 고를 수 없고, 자동 배정에서도 절대 배정하지 않습니다. 학생 화면에는 "지난달 역할"로 표시되고, 억지로 보내면 서버가 거부합니다.
- 같은 달 기록이 여럿이면(예: "2026년 10월"과 "2026년 10월 2차") 가장 최근에 저장한 것을 쓰고, 뒤 달의 기록을 지난달로 쓰는 일은 없습니다. 회차 이름에서 달을 읽을 수 없으면 이 회차의 기록이 아닌 가장 최근 기록을 지난달로 봅니다. 기록은 최대 36개월 보관합니다.
- 공개한 뒤 회차 이름을 바꾸면 그 달 기록의 이름도 따라가고, 같은 회차를 다시 공개하면 기록이 하나로 유지됩니다.
- 학생을 삭제하면 설문·지원서·배정(설명 포함)·달별 기록·AI 분석 결과에서 함께 빠집니다. AI 분석의 서술에 남은 이름은 "(삭제된 학생)"으로 바뀝니다.
- 역할 목록에서 역할을 지우면 그 역할을 맡고 있던 학생은 "아직 배정 안 됨"으로 돌아가고 배정 경고에 표시됩니다. 공개된 배정이었다면 학생 화면에서도 역할이 사라지므로 다시 배정해 주세요.

**성향 설문 (학생 ①)**

- "나는 이런 편이에요": 21개 항목(조용한 편이다, 정리정돈을 잘하는 편이다, 먼저 양보하는 편이다, 새로운 친구와도 금방 친해지는 편이다 등) 중 자기에게 맞는 것을 고릅니다.
- "내 짝은 이런 친구면 좋겠어요": 같은 항목 중 최대 3개를 고르고, 어떤 짝이 좋은지 글로 적을 수 있습니다(300자). 특정 친구의 이름은 적을 수 없고(성을 뺀 이름도 반에서 유일하면 인식), 적으면 저장되지 않습니다.
- 결과는 선생님의 지원 현황 표와 AI 분석·배정의 참고 자료로만 쓰이며, 다른 학생에게는 보이지 않습니다.

**지원서 (학생 ②)**

- 역할 카드를 눌러 1지망 → 2지망 → 3지망 순서로 고릅니다. 1지망은 꼭 있어야 하고, 최대 3개, 같은 역할은 두 번 고를 수 없습니다.
- 지망마다 "하고 싶은 이유"(10자 이상, 필수), "우리 반에 도움 되는 점", "나에게 도움 되는 점"을 적습니다(각 600자).
- 회차가 마감되기 전까지는 다시 낼 수 있고, 새 회차가 시작된 뒤 옛 화면에서 보낸 지원서는 거부됩니다(회차 간 섞임 방지).

**파일로 가져오기 (한글 · 워드 · 텍스트)**

- 역할 목록 칸의 **📄 파일에서 역할 불러오기**, 지난달 현황 칸의 **📄 파일 올리기**로 `.hwp`(한글 5.0), `.hwpx`, `.docx`, `.txt` 파일을 바로 올릴 수 있습니다. 서버가 파일 안의 표와 문단을 읽어 아래 붙여넣기 형식으로 바꾼 뒤 같은 방식으로 미리보기를 만듭니다. 파일은 메모리에서만 읽고 저장하지 않습니다. (최대 6MB, 암호가 걸렸거나 배포용으로 저장한 한글 문서는 읽을 수 없고, 한글 97 등 옛 형식은 한글에서 hwpx 로 다시 저장해 주세요.)
- 역할 목록 파일은 "역할명 | 해야할 일" 처럼 역할 이름 열과 설명 열이 있는 표를 찾아 읽습니다. 이름 칸의 `(2명)`은 인원으로, 괄호 안 글이나 "해리포터, 헤르미온느" 같은 둘째 줄은 부제로 들어가고, 인원이 없으면 1명으로 두고 알려 줍니다. 표가 없으면 `1. 칠판 지우기 (2명)` 같은 제목 줄과 그 아래 설명으로 나눕니다. 읽은 결과는 편집기에만 들어가므로 확인한 뒤 **역할 저장하기**를 눌러야 저장되고, 이미 있는 역할과 이름이 같으면 id 를 이어받아 지원서·기록과 연결이 유지됩니다.
- 지난달 현황 파일은 표의 한 행을 한 줄로(칸은 ` | `로 나눠) 붙여넣기 칸에 넣고 바로 미리보기를 만듭니다. 글을 고친 뒤 **미리보기**를 다시 누를 수 있습니다.

**배정표 복사·내려받기 (한글 · 워드)**

- 결과 내보내기 칸의 **표 복사**는 화면의 표를 진짜 표로 복사합니다(HTML 표 + 탭으로 나눈 글). 한글·워드·구글 문서·알림장에 붙여 넣으면 표가 되고, 엑셀·구글 시트에 붙이면 칸이 나뉩니다.

- 결과 내보내기 칸의 **📄 한글 파일 (.hwpx)** / **📄 워드 파일 (.docx)** 버튼으로 서버에 저장된 배정을 문서로 내려받습니다. 제목, 반 이름·날짜·공개 여부, 그리고 `역할명 | 인원 | 이번 달 담당 (번호 이름)` 표가 들어가고, "학생별 배정 이유 표도 넣기"를 켜면 번호·이름·역할·배정 이유 표가 뒤에 붙습니다. 번호는 학급 명단 순서입니다.
- 내려받은 파일을 다음 달 "지난달 현황 가져오기"에 그대로 올리면 같은 역할 연속 금지 규칙에 쓸 수 있습니다. 미배정 학생을 적은 줄은 어느 역할에도 넣지 않습니다.
- hwpx 는 한글 2014 이상에서 열리는 한글 기본 형식입니다. 한글이 실제로 저장한 문서의 머리 부분(글자 모양·문단 모양 정의, `server/hwpx-template.js`)을 바탕으로 글꼴만 한컴 윤고딕(보통 240 · 굵게 250)으로 통일하고 본문을 만들어 넣으므로(`server/export-docs.js`) 외부 라이브러리 없이 한글이 여는 구조를 유지합니다. 긴 글은 한글이 저장하는 방식 그대로 줄마다 줄 정보를 쓰고(한 줄만 쓰면 글자가 겹쳐 보임), 표는 "글자처럼 취급"하지 않고 쪽 경계에서 나뉘며 제목 줄이 쪽마다 반복됩니다. 혹시 열리지 않으면 워드 파일로 내려받아 한글에서 열어 주세요.
- 파일을 올렸는데 반 명단과 같은 이름이 없으면, 파일에서 읽힌 이름 목록과 읽은 표·문단 수를 함께 보여 주어 원인을 바로 알 수 있습니다. (예: 다른 교실 파일, 이름이 다르게 적힘)

**지난달 현황 가져오기 형식**

한 줄에 역할 하나씩, 역할 이름 뒤에 번호와 이름을 적습니다. 번호는 없어도 되고 구분 기호도 자유입니다.

```
빗자루의 마법사: 8 이준영 24 임민호
칭찬 수집가: 9 정서원 23 이지민
오늘의 아나운서: 20 박한음
```

- 역할은 줄 안에 역할 이름(띄어쓰기 무시, 앞 4글자만 맞아도 됨)이 들어 있는지로 찾고, 여러 이름이 걸리면 가장 긴 이름을 고릅니다. 역할 줄 아래에 이름만 적힌 줄이 이어지면 같은 역할로 들어갑니다.
- 학생은 반 명단의 이름으로 찾습니다. 성을 뺀 이름("준영")도 반에서 유일하면 인식합니다. 같은 학생이 두 번 나오면 나중 역할로 옮깁니다.
- "역할명", "번호", "시간"으로 시작하는 머리글 줄은 건너뜁니다. 어느 역할인지 알 수 없는 줄과 명단에서 이름을 찾지 못한 줄은 미리보기에서 따로 보여 주며, 잘못 들어간 학생은 ✕ 로 빼고 빠진 학생은 선택 상자에서 더할 수 있습니다.
- 미리보기는 저장하지 않으며 "이 달 기록으로 저장"을 눌러야 반영됩니다. 같은 달을 다시 저장하면 덮어쓰고, 달마다 삭제할 수 있습니다. 예시 문서는 `server/roles.js` 의 `SAMPLE_SEPTEMBER` 에 있습니다.

**규칙 배정 점수 계산 방식**

학생 한 명을 어떤 역할에 넣을 때의 점수를 더해 총점이 가장 높은 배정을 찾습니다. 배정 이유는 학생마다 문장으로 보여 줍니다(예: "1지망 ✓ · 이유를 정성껏 적음(84자) · 역할을 잘 이해함").

| 항목 | 점수 |
| --- | --- |
| 지망 순위 | 1지망 100 · 2지망 60 · 3지망 30 (지원하지 않은 역할에 들어가면 0) |
| 정성 | "하고 싶은 이유" 60자 이상 +20, 30자 이상 +10 · "우리 반에 도움 되는 점" 작성 +5 · "나에게 도움 되는 점" 작성 +5 |
| 역할 이해 | 이유에 역할 이름·설명과 겹치는 낱말(한글 2자 이상, 조사와 흔한 말 제외)이 있으면 +5 |
| 감점 | 안 좋은 사이(한쪽이라도 표시) 또는 선생님이 "떨어뜨리기"로 정한 두 학생이 같은 역할에 함께 들어가면 쌍마다 −80 · 배정 못 받은 학생이 있는데 빈자리를 남기면 자리마다 −10 |

- 절대 규칙(점수와 상관없이 항상 지킴): 정원 초과 금지 · 지난달 역할 금지 · 한 학생은 한 역할만 · 없는 역할을 적은 지망은 무시.
- 과정: ① 점수가 높은 지망부터 차례로 배정(같은 점수는 "다시 섞기" 번호에 따라 순서가 바뀌고, 같은 번호면 결과도 같음) → ② 지원서가 없거나 지망이 모두 찬 학생은 지원자가 적은 역할의 빈자리부터 배치 → ③ 한 명 이동·두 명 교환·빈자리 연쇄 이동으로 총점이 오르는 동안 개선.
- 자리보다 학생이 많으면 미배정 학생과 함께 경고를 보여 주고, 안 좋은 사이를 피할 수 없이 같은 역할에 넣게 되면 ⚠ 로 표시합니다. 점수와 감점은 `server/assign.js` 위쪽 상수에서 조정할 수 있습니다.

**AI 배정과의 차이**

- AI 배정은 선생님의 선정 기준과 같은 배정 규칙을 담아 배정안과 학생마다 "아이들 앞에서 그대로 읽어 줄 수 있는 한 문장"을 만듭니다. AI 결과도 서버가 정원·지난달 역할·중복·빠진 학생을 다시 검사해 고치고, 고친 내용은 경고로 알려 줍니다.
- 어느 방법이든 결과는 초안일 뿐이며, 선생님이 고치고 확정해야 학생에게 보입니다. 지난 회차의 배정은 회차 선택에서 그대로 볼 수 있고, JSON 내보내기에는 역할 목록·달별 기록·회차별 설문·지원서·배정이 모두 들어갑니다.

## 학생 몸 특징과 자리 환경 (자리 배정 참고)

학생은 "나는 이런 편이에요" 페이지의 **② 참고해 주세요**에서 눈(시력) · 키 · 추위 · 더위를 각각 하나씩 고릅니다(보통/비워 두기 가능). 이 값은 학생 정보에 남아 회차가 바뀌어도 유지되며, 선생님 페이지 학생 표와 자리 배정 페이지의 "특징" 칸, 종합 보고서에 보입니다.

자리 배정 페이지에서는 **🌀 바람 자리 표시**를 눌러 시스템 에어컨·히터 바람이 바로 닿는 자리를 눌러 표시하고, 옆에서 지금 **냉방 중 / 난방 중 / 꺼짐**을 고릅니다. 자동 배정은 다음을 함께 고려합니다.

- 눈이 나쁜 편 → 앞 두 줄 (교사가 👓 앞자리 필요를 체크한 것보다는 약하게)
- 키가 작은 편 → 앞쪽, 키가 큰 편 → 뒤쪽을 조금 선호
- 냉방 중: 추위를 잘 타는 학생은 바람 자리를 피하고, 더위를 잘 타는 학생은 바람 자리를 조금 선호 (난방 중은 반대)
- 맞지 않는 자리에 앉으면 "참고" 목록과 좌석 색으로 알려 줍니다

바람 자리와 냉난방 상태는 `PUT /api/teacher/<토큰>/seating` 의 `zones`(좌석 → `ac`) 와 `climate`(`cool` · `warm` · `off`) 로 저장됩니다.

## 역할 자리 (1인 1역 담당 학생이 앉는 자리)

1인 1역 역할 목록을 만들어 두면 자리 배정 페이지에 **🎒 역할 자리 지정** 버튼이 생깁니다. 역할을 고른 뒤 자리를 누르면 그 자리는 "이번 회차에 그 역할을 맡은 학생"이 앉는 자리가 됩니다(같은 역할 자리를 다시 누르면 해제). 칠판 담당은 칠판 앞, 우유 당번은 문 옆처럼 역할에 맞는 자리를 한 번 정해 두면, 매달 담당 학생이 바뀌어도 자리는 그대로 두면 됩니다.

- 자동 배정과 AI 자리 배정은 역할 자리에 그 역할의 담당 학생(1인 1역 배정표에 지금 저장된 배정 — 초안이든 공개본이든)을 먼저 앉히고 📌 고정 자리처럼 움직이지 않습니다. 이미 자기 역할 자리에 앉아 있는 담당은 그 자리에 그대로 둡니다. 담당 학생이 아직 없거나 담당보다 역할 자리가 많으면 남는 역할 자리는 보통 자리로 씁니다(경고도 붙지 않습니다).
- 담당이 아닌 학생이 역할 자리에 앉아 있거나 담당 학생이 다른 자리에 있으면 "참고" 목록과 좌석 색으로 알려 줍니다.
- 종합 보고서의 자리표에는 역할 이름이 작은 배지로 붙고, 자리 배정 참고 목록에 "🎒 역할 자리: 역할명 → N분단 n번째 줄 m번째 자리 (담당: 이름)" 줄이 들어갑니다. 한글·워드 파일에서는 그 칸의 둘째 줄에 "(역할명)"으로 나옵니다.
- 역할 자리는 `PUT /api/teacher/<토큰>/seating` 의 `roleSeats`(좌석 id → 역할 id) 로 저장되며, 역할 목록에 없는 역할이면 400 으로 거부합니다. 역할을 지우면 그 역할 자리도 함께 지워집니다.

## AI 자리 배정 (선택)

서버에 `ANTHROPIC_API_KEY` 가 설정되어 있으면 자리 배정 페이지의 **🤖 AI 자리 배정** 버튼을 쓸 수 있습니다. 지금 화면의 배치 · 📌 고정 자리 · 🌀 바람 자리와 냉난방 상태 · 🎒 역할 자리 · 친한 친구 옵션을 기준으로, AI 가 학생 응답(좋은/안 좋은 사이와 이유), 규칙 기반 갈등 가능성, 선생님 메모와 떨어뜨리기/가까이 앉히기 규칙, 앞자리 필요, 몸 특징, 성향 설문, 지난 AI 분석, 1인 1역 배정을 함께 읽고 배정안을 만듭니다.

- 버튼을 누르면 화면에 적어 둔 교사 메모·👓 앞자리·떨어뜨리기/가까이 앉히기 규칙을 **먼저 저장한 뒤** AI 에 보냅니다(서버는 저장된 메모·규칙을 읽습니다). 학생이 한 명도 없으면 AI 를 부르지 않습니다.
- 결과는 화면에 바로 반영되지만 **자리는 저장되지 않습니다.** 자리를 확인하고 고친 뒤 "저장"을 눌러야 자리표가 됩니다. 마지막 배정안은 교실에 남아(`aiSeating`) 측면 카드의 "🤖 AI 자리 배정 메모"에서 AI 가 쓴 메모, AI 가 예측한 갈등 가능성 상위 쌍, 학생별 설명을 볼 수 있고 "AI 배정안 다시 적용"으로 다시 불러올 수 있습니다. 그 사이 배치나 명단이 달라졌으면 배정안에 자리가 없는 학생은 앞줄 빈자리부터 앉히고 몇 명이 그렇게 됐는지 알려 줍니다.
- 배정안을 만든 회차를 지우면(또는 보관 기간이 지나 자동 삭제되면) 그 배정안도 함께 지워지고, 학생 이름을 바꾸면 배정안·AI 분석 글 속 이름도 같이 바뀝니다. 프롬프트의 규칙 기반 갈등 추정은 가능성 높은 순 40쌍까지만 넣어, 큰 반에서도 학생이 직접 적은 관계·설문이 길이 제한에 밀려 잘리지 않게 합니다.
- AI 가 돌려준 쌍별 갈등 가능성(%)은 자동 배정 점수와 "참고" 경고에도 쓰입니다. 학생이 안 좋은 사이로 표시하지 않았어도 AI 가 40% 이상으로 본 쌍이 이웃이면 경고가 붙고, 규칙 기반 %와 AI %가 둘 다 있으면 함께 보여 줍니다("갈등 72% · AI 65%").
- 서버는 AI 의 배정안을 받은 뒤 다시 검사합니다(`server/seating.js` 의 `repairSeating`). 배치에 없는 좌석과 모르는 학생은 버리고, 📌 고정 자리와 🎒 역할 자리를 지키고, 한 학생은 한 자리만 앉히고, 자리가 없는 학생은 앞줄부터 빈자리에 채우고, 자리가 모자라면 안내합니다.
- 종합 보고서: 보고서를 보는 회차와 같은 회차에서 만든 배정안이면 자리 배정 섹션 끝에 "AI 자리 배정 메모"(AI 메모 · AI 예측 갈등 가능성 상위 10쌍)가 들어갑니다.
- **비용과 시간**: 한 번에 30초~1분쯤 걸리고 API 사용량(비용)이 듭니다. 버튼을 누르면 먼저 확인 창이 뜹니다. 배포 환경의 함수 실행 시간 제한은 아래 "AI 분석 설정"의 안내와 같습니다.
- **API**: `POST /api/teacher/<토큰>/ai/seating` — 본문은 `PUT …/seating` 과 같은 모양(`layout`, `seats`, `pinned`, `zones`, `climate`, `roleSeats`, `options`)에 `roundId` 를 더한 것입니다. 응답은 선생님 화면 데이터 전체이고, 그 안의 `aiSeating` 에 `{ roundId, roundName, createdAt, model, truncated, pairs: [{ a, b, probability, reason }], assignment: { 좌석 → 학생 }, explanations: { 학생 → 설명 }, notes, warnings }` 가 들어 있습니다. 키가 없으면 400 과 안내 문구를 돌려줍니다.
- **가명 처리**: AI 분석·AI 배정과 같습니다. 학생 실명과 내부 번호, 관리 토큰은 보내지 않고 S1, S2… 가명으로 바꾸며, 메모·이유·지난 분석 글 안의 반 친구 이름(역할 이름 속 이름 포함)도 가립니다. 좌석은 "b0-r0-c0: 1분단 1번째 줄 왼쪽(앞줄)"처럼 id 와 설명을 함께 보냅니다. 학생을 삭제하면 배정안에서 그 학생의 자리·쌍·설명을 지우고, 글에 남은 이름은 "(삭제된 학생)"으로 바꿉니다.

## 종합 보고서

선생님 페이지 위쪽 이동 줄의 **📑 보고서** 버튼(또는 데이터 관리 카드의 "보고서 보기")을 누르면 `/t/<관리 토큰>/report` 가 열립니다. 보고 있는 회차를 바꿔 가며 볼 수 있고, 내용은 다음 순서로 들어갑니다.

1. 한눈에 보기 — 제출, 좋은/안 좋은 사이 수, 주의가 필요한 관계, 고립 위험
2. 학생별 관계 — 받은/보낸 지목 수와 표시(고립 위험 · 지목 많음 · 갈등 많음)
3. 갈등 가능성 분석 — 가능성 높은 순으로 20쌍까지, 주요 근거 포함
4. AI 분석 — AI 분석을 돌린 회차에만 (학급 요약 · 눈여겨볼 관계 · 학생별 요약)
5. 자리 배정 — 저장한 자리표(학생 시점, 칠판이 위, 🌀 바람 자리와 🎒 역할 자리 표시)와 선생님 메모·규칙·역할 자리 목록, 같은 회차에서 만든 AI 자리 배정 메모
6. 1인 1역 — 이번 달 배정표, 원하면 학생별 배정 이유 표(선생님 참고용)
7. 회차별 변화 — 회차가 둘 이상일 때 추세 표와 새로 생긴·계속되는·해소된 갈등

- **인쇄 / PDF**: 브라우저 인쇄 창에서 "PDF로 저장"을 고르면 PDF 가 됩니다. 위쪽 메뉴와 조절 줄은 인쇄에 나오지 않습니다.
- **한글 · 워드 파일**: `GET /api/teacher/<토큰>/report.hwpx` · `report.docx` (`?round=<회차 id>&reasons=1`) 로 내려받습니다. 문서 모델은 `GET …/report.json` 으로도 볼 수 있습니다.
- 보고서에는 학생 이름이 그대로 들어가므로 보관·공유에 주의해 주세요. 수치와 AI 분석은 참고용입니다.

## AI 분석 설정 (선택)

AI 기능은 선택 사항입니다. 설정하지 않아도 관계도, 갈등 가능성 분석, 자리 배정, 규칙 배정 등 나머지 기능은 모두 동작합니다.

**무엇을 하나요?**

- AI 관계 분석: 학생 응답, 규칙 기반 갈등 추정, 선생님 메모와 규칙, 성향 설문, 지원서를 함께 읽고 학급 분위기 요약, 눈여겨볼 학생 쌍(위험도·갈등 성격·분석·교실에서 할 수 있는 조치), 학생별 요약·강점·살펴볼 점·잘 맞는 역할을 돌려줍니다. 결과는 회차에 저장되어 다시 열어도 보이고, 지원 현황 표의 "AI 분석 참고"에도 나타납니다.
- AI 배정: 위 "1인 1역" 항목의 설명대로 배정안과 학생별 한 문장을 만듭니다.
- AI 자리 배정: 위 "AI 자리 배정" 항목의 설명대로 자리 배정안, 쌍별 갈등 가능성 예측, 학생별 설명을 만듭니다.

**환경 변수**

| 환경 변수 | 설명 | 기본값 |
| --- | --- | --- |
| `ANTHROPIC_API_KEY` | 필수. https://console.anthropic.com 에서 발급한 Anthropic API 키 | 없음 (AI 기능 꺼짐) |
| `AI_MODEL` | 사용할 모델 이름 | `claude-opus-5-5` |

**설정 방법**

- Vercel: 프로젝트 화면에서 **Settings → Environment Variables** 로 가서 Key 에 `ANTHROPIC_API_KEY`, Value 에 키를 넣고 환경(Production, Preview, Development)을 체크한 뒤 **Save** 를 누릅니다. 그다음 **Deployments** 탭에서 맨 위 배포의 **⋯ → Redeploy** 를 눌러야 반영됩니다. `AI_MODEL` 도 같은 방법으로 넣습니다.
- 내 컴퓨터: `ANTHROPIC_API_KEY=sk-ant-... npm start` 처럼 앞에 붙여 실행하거나, 터미널에서 `export ANTHROPIC_API_KEY=sk-ant-...` 를 한 뒤 `npm start` 합니다. Windows PowerShell 은 `$env:ANTHROPIC_API_KEY="sk-ant-..."` 입니다.
- Render·Docker 등: 서비스의 환경 변수 설정에 넣거나 `docker run -e ANTHROPIC_API_KEY=... ` 로 넘깁니다.
- 설정이 끝나면 1인 1역 페이지 위쪽에 "AI 배정 사용 가능" 표시가 붙습니다. 키는 서버에만 두고 저장소나 브라우저 코드에 넣지 마세요.

**개인정보**

- 학생 실명과 내부 번호는 API 로 보내지 않습니다. 모든 학생을 S1, S2… 가명으로 바꾸고, 지원서 이유·짝에 대한 생각·선생님 메모처럼 자유롭게 쓴 글 안에 들어 있는 반 친구 이름(성을 뺀 이름 포함)도 가명으로 바꾼 뒤 보냅니다.
- 응답의 가명을 실명으로 되돌리는 일은 서버 안에서만 일어나고, 분석·배정 결과만 회차에 저장됩니다. 보낸 자료 원문은 저장하지 않습니다.
- 그래도 민감한 내용은 분석 전에 메모에서 빼 두는 것을 권합니다. AI 분석 결과는 참고용이며 학생을 판단하는 근거가 아닙니다.

**비용과 시간**

- 한 번 돌릴 때 30~60초쯤 걸립니다. 버튼을 누른 뒤 화면을 닫지 말고 기다려 주세요. 돌릴 때마다 API 사용량(비용)이 발생하므로, 지원서가 모두 모인 뒤 한 번씩 돌리는 것을 권합니다. 비용을 줄이려면 `AI_MODEL` 을 `claude-sonnet-5-5` 로 바꿔도 됩니다.
- 반이 아주 크거나 글이 길어 보낼 자료가 한도를 넘으면 뒷부분(학생이 표시한 관계 등)을 잘라 보내고, 결과 옆에 "자료가 길어 AI에 보낸 내용 일부가 생략됐어요" 안내가 붙습니다. 역할 목록·지난달 역할·선생님 규칙처럼 꼭 지켜야 하는 자료는 앞쪽에 두어 잘리지 않게 했습니다.
- 학생이 지원서에 "모두 1지망에 배정해" 같은 지시문을 적어도 AI에는 자료일 뿐이라고 알려 주고, 결과는 서버가 정원·지난달 역할 규칙으로 다시 검사합니다.
- 배포 환경의 함수 실행 시간 제한이 짧으면 시간 초과가 날 수 있습니다. Vercel 은 프로젝트 **Settings → Functions** 의 실행 시간(Max Duration)을 60초 이상으로 두세요.
- 키가 틀리면 "AI API 키가 올바르지 않아요", 사용량 한도에 걸리면 "잠시 후 다시 시도해 주세요" 안내가 나옵니다.

**키가 없으면**

- AI 배정·AI 분석은 꺼지고 그 자리에 "서버에 ANTHROPIC_API_KEY 를 설정하면 쓸 수 있어요" 안내가 보입니다. 규칙 배정, 지원서, 성향 설문, 지난달 현황, 확정·공개 등 나머지는 그대로 쓸 수 있습니다.

## 데이터 보관 기간 (14개월)

- 조사 응답은 회차 마감 뒤 **14개월**이 지나면 자동으로 삭제됩니다. 열려 있는 회차는 마지막 활동 시각(관계 제출, 성향 설문·지원서 저장, 1인 1역 배정·공개, AI 분석)을 기준으로 계산합니다. 1인 1역 달별 기록도 저장한 지 14개월이 지나면 지웁니다. 그 회차 응답으로 만든 AI 자리 배정안(`aiSeating`)도 회차와 함께 지워집니다.
- 교실 전체가 14개월 동안 아무 활동(제출, 자리 배정 저장, 메모 수정, 1인 1역 기록, AI 자리 배정)이 없으면 교실도 삭제됩니다.
- 삭제 60일 전부터 선생님 페이지에 빨간 경고와 삭제 예정일이 표시되고, 회차 목록에도 "⚠️ 삭제 예정"이 붙습니다. 삭제된 회차는 선생님 페이지 아래에 "최근 자동 삭제" 기록으로 남습니다.
- 삭제는 두 겹으로 돌아갑니다. Vercel 에서는 `vercel.json` 의 예약 작업이 매일 새벽 3시(한국 시간)에 `/api/maintenance/purge` 를 호출하고, 일반 서버에서는 시작할 때와 하루에 한 번 실행됩니다. 그 밖에도 교실을 열 때마다 검사합니다.
- 오래 보관하려면 선생님 페이지의 **CSV/JSON 내보내기**로 파일을 받아 두세요. JSON 에는 모든 회차와 분석이 들어 있습니다.
- 기간을 바꾸려면 환경 변수 `RETENTION_MONTHS` 를 설정하세요. `CRON_SECRET` 을 설정하면 예약 작업 주소를 그 값 없이는 호출할 수 없습니다 (Vercel 은 자동으로 붙여 줍니다).

## 메모 자동 분류 방식

자리 배정 페이지의 "한 번에 붙여넣기"는 규칙 기반으로 동작합니다.

- 줄과 문장 부호로 문장을 나누고, 문장 안에서 반 명단의 이름을 찾습니다. 성을 뺀 이름("하늘이")도 반에서 유일하면 인식합니다.
- 시력·안경·앞자리·칠판 같은 표현이 있으면 **앞자리 필요**로 표시합니다.
- 두 명 이상이 함께 나오고 싸움·다툼·갈등·떨어뜨리기·괴롭힘 같은 표현이 있으면 **떨어뜨리기**, 도우미·짝·같이 앉히기·친함 같은 표현이면 **가까이 앉히기** 규칙을 만듭니다. 두 표현이 함께 있으면 문장 끝에 가까운 쪽을 따릅니다. ("예전엔 싸웠지만 요즘은 같이 앉혀도 됨" → 가까이 앉히기)
- "붙여 앉히면 수업 방해"처럼 같이 앉았을 때의 문제를 적은 문장은 떨어뜨리기로 봅니다.
- 그 밖의 문장은 언급된 학생의 **메모**로 들어가고, 학생 이름이 없는 문장은 "찾지 못한 문장"으로 따로 보여 줍니다.

표현 목록은 `public/js/notes-parser.js` 의 `KEYWORDS` 에서 바꿀 수 있습니다.

## 글꼴

사이트 전체에 강원특별자치도교육청이 무료로 배포한 **강원교육모두체**(Bold)를 씁니다. `public/fonts/GangwonEduAll-Bold.woff2` 는 원본 TTF 에서 한글 전체(11,172자)와 영문·기호만 남겨 WOFF2 로 변환한 파일이라 245KB 로 가볍습니다. 외부 글꼴 서비스에 의존하지 않으므로 인터넷이 느린 교실에서도 빠르게 뜹니다.

## 갈등 확률 계산 방식

학생 응답만으로 계산하는 규칙 기반 추정치이며, 근거를 함께 보여 줍니다.

1. 시작값: 서로 안 좋은 사이 78% · 한쪽만 안 좋은 사이 48% · 한쪽은 좋고 한쪽은 안 좋음 40% · 한쪽만 좋은 사이 8% · 서로 좋은 사이 4%
2. 안 좋은 이유의 심각도: 때리거나 괴롭힘 +15, 무시하거나 따돌림 +12, 놀림·험담 +10, 싸운 적 있음 +10, 말을 함부로 함 +6 등 (최대 +25)
3. 공통 친구 수: 같은 무리에서 자주 마주치므로 +4/명 (최대 +12)
4. 3명 이상에게 안 좋은 사이로 지목된 학생이 포함되면 +6, 좋은 사이로 지목한 학생이 아무도 없는(고립 위험) 학생이 포함되면 +5
5. 결과는 2~97% 사이로 제한하고, 70% 이상은 "높음", 40% 이상은 "주의"로 표시

관계 정보가 전혀 없는 쌍은 계산하지 않습니다. 이 수치는 학생을 판단하는 근거가 아니라 먼저 관심을 기울일 관계를 찾기 위한 참고용입니다. 규칙은 `server/analysis.js`에서 조정할 수 있고, 이유 선택지와 가중치는 `server/reasons.js`에 있습니다.

## 개인정보와 안전

- 학생 링크와 선생님 링크는 추측할 수 없는 임의 문자열입니다. 선생님 링크는 교실에 들어가는 유일한 열쇠이므로 안전하게 보관하세요.
- 학생 API는 본인의 응답과 반 친구 이름만 돌려주며, 다른 학생의 응답이나 링크는 노출하지 않습니다.
- 링크가 유출되면 선생님 페이지에서 해당 학생의 링크를 재발급할 수 있습니다.
- 서버는 로그인 없이 링크만으로 동작하므로, HTTPS가 적용된 곳에 배포하는 것을 권장합니다.
